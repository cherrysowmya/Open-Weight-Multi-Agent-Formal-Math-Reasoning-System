# V5 — minimal formal specialist

V5 is **opt-in**, supported by `solve` and the separately labelled
`intro-logic-run --variant v5` benchmark condition (see [logic benchmark](intro-logic.md)). Qwen remains the orchestrator
and handles informal reasoning, verification of informal plans, and discussion.
DeepSeek-Prover-V2-7B is a bounded formal proof-generation tool, not an authority.
There is no tactic portfolio and no paid inference API.

## Setup and use

Install the project's pinned inference dependencies, not an unconstrained
Transformers upgrade:

```bash
.venv/bin/pip install -e '.[mlx]'
```

The validated tokenizer stack is Transformers 5.0.0, tokenizers 0.22.2 and
huggingface-hub 1.32.0 with MLX-LM 0.31.3. The previously installed Transformers
5.16.1 path corrupted DeepSeek Lean inputs. Managed model startup now checks
Unicode/whitespace and chat-template round trips before launching MLX. See
[tokenizer hardening](v5-tokenizer-hardening.md) for evidence and validation status.

The default specialist is the existing MLX conversion
[`mlx-community/DeepSeek-Prover-V2-7B-4bit`](https://huggingface.co/mlx-community/DeepSeek-Prover-V2-7B-4bit).
Its card identifies the source as DeepSeek-Prover-V2-7B. The upstream
[model card](https://huggingface.co/deepseek-ai/DeepSeek-Prover-V2-7B) demonstrates
a proof-plan-plus-Lean response; our adapter uses a concise plan and one fenced
proof body, preserving the original task in Python. This shorter prompt and
budget are local engineering choices, not a reproduction of published scores.

From the project root, download the weights once (network and disk space needed,
no inference or second loaded model):

```bash
bash scripts/setup-formal-specialist.sh
```

The script forwards optional `hf download` arguments, including `--revision` for
an immutable Hugging Face commit. It uses the same default cache as MLX-LM.
For reproducible experiments, set `[specialist].model_id` to the printed local
snapshot path; record that revision. Do not treat a moving repository name as a
pinned model. The model is not downloaded as part of tests or installation.

Start Kimina using the existing documented workflow, then run:

```bash
HF_HUB_OFFLINE=1 .venv/bin/local-lean-agent --config config/local.toml solve \
  examples/demo_repair.lean --live --proof-format proof_body \
  --informal-policy always --v4 on --v5 on --max-rounds 3
```

All needed models must already be cached when `HF_HUB_OFFLINE=1` is used. Without
offline mode, MLX-LM can download an uncached model during first startup/inference.
No proprietary API is used in either case. A missing/incompatible model produces
a recorded failure, not a fabricated proof or a silent fallback to Qwen.

The easy repair demo may succeed with Qwen immediately, in which case **the
specialist correctly receives zero calls**. `--v5 on` enables conditional routing;
it does not force unnecessary specialist work. At least two formal rounds must
be available to exercise V5. `--v5 off` keeps the earlier solver behavior.

## Routing and budgets

1. Check a concrete input proof first, as before.
2. Qwen attempts a formal proof. An invalid input seed alone does not trigger V5.
3. After a failed model-generated formal attempt, the next available formal
   round is assigned to the specialist (before V4 discussion on that round).
4. Build a fresh task packet before switching. It contains the immutable theorem,
   imports and hypotheses, current goal, recent diagnostics, bounded retrieval
   records, optional informal outline, and explicit rejected candidate/error pairs.
   No whole conversation or hidden reasoning history is passed.
5. Unload Qwen synchronously, then load DeepSeek using the same backend/server
   endpoint. A failed unload prevents the next load. Only one owned model is
   resident at a time. Unmanaged external MLX servers are rejected for V5.
6. Request exactly one candidate. The initial limits are 8,192 total estimated
   input + reserved output tokens and 2,048 output tokens. The existing
   conservative context guard applies; task/goal text is never cut.
7. Extract one complete `lean` or `lean4` fence, assemble it into the original
   proof slot, and run the existing integrity and Kimina/Lean checks. Malformed
   output, changed statements and unresolved placeholders cannot count as success.
   An exact duplicate of an already rejected proof reuses its rejection, never
   a success; distinct admissible candidates are independently checked.
8. If accepted, unload DeepSeek and finish without reloading Qwen. If rejected
   and a formal round remains, reload Qwen with the new failure evidence.

`--max-rounds 3` remains **three total formal model candidates**, not three Qwen
candidates plus extra specialist attempts. Informal/discussion calls retain
their separately bounded budgets. The initial specialist cap is one invocation
per theorem. Inference timeout/startup errors terminate the attempt with details
instead of spending extra hidden attempts. V5 always unloads its owned model at
attempt completion, regardless of the older keep-loaded option.

Settings live in `[specialist]` in `config/local.toml`; it defaults to disabled.
The adapter is specific to DeepSeek-Prover-V2. A configurable model path supports
local snapshots, not a claim that every other specialist has been integrated.
Goedel comparison and full V6 routing are not implemented here.

## Interfaces and instrumentation

- `specialist.py`: isolated packet construction, DeepSeek prompt and response adapter.
- `model_router.py`: single-resident-model lifecycle through `ModelBackend`.
- `backends/mlx.py`: managed process ownership and synchronous termination.
- `orchestrator.py`: failure trigger, shared formal budget, assembly and verification.

Agent logic does not call MLX APIs. A future backend must implement the existing
provider-neutral interface and truthfully declare `supports_model_switching`
before being used for V5. There is no vLLM implementation in this change.

Live terminal output names the specialist and model load/unload stages. The
normal run directory contains `events.jsonl`, the full result JSON, and a verified
proof only when successful. New instrumentation includes:

- `specialist_requests`: fresh context IDs, exact requests, budgets, completion,
  finish reason, status and errors;
- iteration `role="formal_specialist"` and `repair_action="formal_specialist"`;
- specialist calls, token subtotals and Lean-verified specialist successes;
- per-model load/unload transitions, elapsed times, errors and aggregate times;
- memory samples during formal inference and `model_peak_sampled_rss_mb`.

`model_calls`/terminal `formal` counts all completed formal calls, including the
specialist. The specialist token counts are **subtotals** of formal token totals;
do not add them again. Failed requests have their own request/error records and
call-attempt counts, even when no completed generation exists.

Memory is sampled process RSS at one-second intervals plus boundary samples,
not exact Metal allocation accounting or a guarantee of total unified-memory
headroom. It does not include all Lean/Docker/OS memory. Real 32 GB profiling
remains necessary. Load time measures server readiness; lazy inference warmup
may instead appear in generation latency.

Existing V1–V4 and MiniF2F benchmark labels must not silently include V5: the CLI
rejects those benchmark commands with the specialist enabled. The logic benchmark
supports an explicit `v5` condition, forcing it off in non-V5 comparison conditions.
A measured V5 accuracy improvement remains to be established.

## Validation and current limits

2026-09-22: **344 tests discovered, 328 passed, 16 opt-in tests skipped.**
The 27 new offline V5 tests cover budget accounting, safe switching and cleanup,
restart failure, interruption, no unnecessary reloads, malformed/duplicate/unsafe
outputs, immutable assembly, isolated packets, context limits, role priority,
metrics, CLI flags and benchmark contamination guards. The original context
hardening tests also pass.

Two additional opt-in tests distinguish wiring from model quality:

```bash
# Real Kimina with scripted model replies: tests verification integration.
LOCAL_LEAN_AGENT_V5_LIVE_LEAN=1 .venv/bin/python -m unittest \
  tests.test_v5.V5LeanIntegration -v

# Real DeepSeek/MLX plus Kimina: requires cached model weights.
HF_HUB_OFFLINE=1 LOCAL_LEAN_AGENT_V5_LIVE_MLX=1 .venv/bin/python -m unittest \
  tests.test_v5.V5ModelSmoke -v
```

The real-model smoke invokes the specialist directly on a trivial theorem to
ensure it is exercised; it does not measure Qwen-to-specialist routing accuracy.
Local tests remain Git-ignored under the existing runtime-only repository policy.

**Post-fix live V5 validation is pending.** The original five-problem V5 run
completed with 2/5 Qwen successes, but all three specialist outputs were rejected
before Lean. A subsequent tokenizer round-trip check reproduced input corruption;
the dependency fix and startup guard pass offline checks. The real specialist
smoke test and corrected benchmark have been deferred to avoid overlapping the
user's running all-88 V4 evaluation. No post-fix specialist proof success or
accuracy improvement is claimed. See the hardening report linked above.
