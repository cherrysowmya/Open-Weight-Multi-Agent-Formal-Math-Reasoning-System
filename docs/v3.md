# V3 — isolated informal reasoning

## Implemented boundary

V3 adds two roles backed by the already-loaded Qwen3-8B model:

- an informal proof generator with thinking enabled;
- an independent informal proof verifier with thinking enabled.

They are provider-neutral users of `ModelBackend`. The concrete local run still
uses `MLXBackend`; no paid service or second model instance is introduced. A
future vLLM backend can serve the same calls without changing the V3 loop.

Each generator or verifier call is a new two-message request with an 8,192-token
configured maximum (input plus reserved output), checked using a conservative
token estimate. Actual prompt usage is also recorded; the estimate is not an
exact tokenizer guarantee for arbitrary input. The verifier receives the immutable task packet and current informal
proof, but no generator transcript, hidden reasoning, or previous verifier
conversation. On a `REVISE` verdict, the next generator request receives only
the task packet, prior outline, and explicit critique. This is context isolation,
not statistical independence: both roles still use the same weights.

The task packet contains only the theorem statement, current LSP goal, bounded
LeanExplore declarations, recent Lean diagnostics, and a bounded summary of
rejected strategies. It never contains the full main-agent conversation.

The default policy is adaptive. Informal reasoning runs once after one rejected
model-generated Lean candidate, not after a deliberately invalid input seed.
Already-valid input candidates and first-round successes pay no informal cost.
Set `invocation_policy = "always"` for a deliberately front-loaded experiment.
The refinement budget is three rounds and configuration rejects values above
five or contexts above 8K.

Informal output is advisory. Even a JSON `PASS` verdict (internal `accept`) only adds a mathematical
outline to the next main-agent prompt. It cannot set attempt success, bypass
Kimina, or create a proof. Every formal candidate must still preserve the task
and pass Lean/Kimina.

## Configuration

The main V3 controls in `config/local.toml` are:

| Setting | Local default | Meaning |
| --- | ---: | --- |
| `enabled` | `true` | Enable the optional V3 layer for ordinary solves |
| `verifier_enabled` | `true` | Disable only for the explicit generator-only ablation |
| `invocation_policy` | `after_model_failures` | Invoke adaptively after formal failure |
| `trigger_after_failures` | `1` | Rejected model candidates before invocation |
| `max_refinement_rounds` | `3` | Generator/verifier refinement pairs, capped at 5 |
| `max_context_tokens` | `8192` | Limit for each isolated request |
| `max_output_tokens` | `1536` | Limit for each informal response |

The main orchestrator remains thinking-disabled and capped at 12,288 tokens.
All V3 roles share one loaded Qwen server sequentially, avoiding extra 8B model
instances on the 32 GB Mac. RSS samples are not a measurement of peak total
unified memory or Metal allocations. V1 and V2 benchmark commands
explicitly disable V3 so their experimental boundaries do not drift.

## Validation and paired experiment

Validate all eight deliberately broken repair seeds and all 18 hidden positive
references without loading Qwen:

```bash
local-lean-agent --config config/local.toml v3-validate \
  --output runs/v3-validation-latest.json
```

Run the 20-case paired experiment (40 theorem attempts):

```bash
local-lean-agent --config config/local.toml v3-ablation \
  benchmarks/v3/manifest.toml \
  --output runs/v3-ablation-latest.json
```

Both conditions keep LeanExplore and required Lean-LSP-MCP enabled, use the same
main Qwen settings and formal round budgets, and disable both the whole-proof
fallback portfolio and compiler-prefix probes. The treatment is informal
reasoning OFF versus ON, including configured V3 strategy-search/rewrite-prompt
hooks. This is a package comparison; isolating informal text requires disabling
those hooks in separate feature ablations. Condition
order alternates by case and repetition. The output checkpoints after every
attempt and preserves a final immutable artifact under `runs/history/`.

The 20 cases contain 10 generation tasks, eight concrete rejected repair seeds,
and two false theorems. They emphasize implication structure, conjunctions,
injectivity, set extensionality, nonlinear signs, divisibility, polynomial
normalization, and list reversal rather than only declaration lookup.

After a completed run, independently recompile accepted and rejected final
candidates and check the negative budgets:

```bash
.venv/bin/python scripts/audit-v3.py runs/v3-ablation-latest.json
```

## Metrics and interpretation

The paired output reports positive success, correct outcomes, formal proof
failures, main-agent calls, wall time, and paired wins/losses. V3-specific
metrics include triggered cases, accepted informal reviews, refinement counts,
generator calls, verifier calls, and informal prompt/completion tokens. Full
attempt files also retain every outline, critique, verdict, context estimate,
latency, and memory sample.

`experiment_complete` means both conditions finished without infrastructure
failures or negative false positives. `informal_invoked` records triggering;
`informal_exercised` requires at least one completed non-malformed review.
`informal_pipeline_healthy` additionally requires no informal-stage errors.
Output-budget exhaustion is logged and counted, never accepted or hidden as
zero calls. Runtime/transport errors in the optional stage let ordinary solving
continue, but make a paired experiment incomplete. None of these flags claims
improvement in mathematics or formalization.

This 20-case suite is a minimum viable integration and diagnostic experiment.
It can reveal gross regressions and provide paired traces, but it is not enough
for a broad research claim. Good engineering improvements include robust
structured-output recovery and total unified-memory profiling. Potentially
publishable work requires a larger held-out corpus, repeated runs, matched total
token or wall-clock budgets, uncertainty estimates, and manual classification
of mathematical versus formalization failures.
